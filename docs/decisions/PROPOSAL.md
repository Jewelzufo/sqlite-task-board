**Audience:** Coding agent implementing this proposal

## 4. Implementation tasks (in order)

### Task 1 — Untrack generated files

```bash
git rm --cached tasks.db __pycache__/agent.cpython-312.pyc
git rm -r --cached assets/images        # or move to docs/assets first
```

Replace `.gitignore` with the block above. Do not delete `tasks.db` from disk; it is local state.

**Acceptance:** `git ls-files` contains no `*.db`, `__pycache__`, or `assets/images`.

### Task 2 — Collapse to one configuration

1. Delete `config.example.yaml`.
2. Keep `config.yaml`; add comments documenting each key. Do not change its structure unless `agent.py` changes first.
3. Update `AGENTS.md` §2 (tree), §4 (config files), §20 (acceptance) and `tests/test_agent_contract.py::test_config_example_yaml_exists`.
4. Update `README.md` §Configuration to reference `config.yaml` only.

**Acceptance:** exactly one tracked YAML config; no doc instructs copying an example.

### Task 3 — Make the runtime usable

Edit `agent.py` only (keep it single-file):

- `--init`: apply `migrations/0001_initial.sql`, execute `seeds/bootstrap_tasks.sql`, create `workspace/logs`, `workspace/data`, `workspace/tmp`. Must be idempotent (`INSERT OR IGNORE` already handles re-seeding).
- `--status`: print counts by `status` and `priority`, plus the next eligible task id. Emit JSONL when `logging.format == "jsonl"`.
- Read `AGENT_CONFIG` for the config path, defaulting to `ROOT / "config.yaml"`.
- `_load_config()`: on missing PyYAML, bad YAML, or unreadable file, print a structured `CONFIG_LOAD_FAILED` event and exit 1 — never a traceback.
- `_validate_payload()` (`agent.py:165-167`): fail closed when `jsonschema` is missing. Current code silently skips validation.
- Remove the inline fallback schema at `agent.py:106`; require the migration file and fail with a clear error if absent.
- Add a schema-version check against `schema_migrations` (cheap, already promised by `README.md:212`).
- Keep `shell=False`, timeouts, host/protocol allowlists, and path-boundary checks unchanged.

**Acceptance:** from a clean clone, `python agent.py --init && python agent.py --check && python agent.py --status` succeeds (the `taskboard` alias arrives in Task 4); running `--init` twice leaves exactly 3 seeded tasks.

### Task 4 — Packaging and entrypoint

Add `pyproject.toml`:

```toml
[project]
name = "sqlite-task-board"
requires-python = ">=3.11"
dependencies = ["pyyaml>=6.0.0", "jsonschema>=4.0.0"]

[project.optional-dependencies]
dev = ["pytest>=8.0.0"]

[project.scripts]
taskboard = "agent:main"
```

Use setuptools with `py-modules = ["agent"]`. Remove `requirements.txt` and update all references in `README.md` / `AGENTS.md`. A `Makefile` (`setup`, `init`, `check`, `run`, `status`) is optional; the console script is the cross-platform path.

**Acceptance:** `pip install -e '.[dev]'` then `taskboard --check` works without activating a package layout.

### Task 5 — Rewrite the docs

- `README.md`: quickstart first (5 commands), then concepts, actions, configuration, troubleshooting. Delete every duplicate section after “Source of truth” (`README.md:374-405`). Target <=120 lines.
- `AGENTS.md`: keep bootstrap sequence, security model, action contract, error codes. Remove prose duplicated from README and full JSON schemas that already live in `ACTION_SCHEMAS`; state that the code is authoritative.
- `opencode.json`: set `"bash": "allow"` for autonomous bootstrap, or add a note that prompts are expected.

**Acceptance:** no duplicated headings across docs; `wc -l README.md` <= 120; quickstart commands run verbatim.

### Task 6 — Reconcile the documented action surface

`README.md:101-107`, `AGENTS.md` §7/§13, and `agent.py:39-72` disagree: docs list five actions, code implements three.

Choose one and apply it everywhere:

- **Preferred for this iteration:** reduce the documented minimum to `verify_runtime`, `create_directories`, `run_health_check`, and delete `setup_env_file` / `install_dependencies` from README and AGENTS.
- **Alternative:** implement both actions with the strict schemas already in `AGENTS.md` §13 (workspace boundary, registry allowlist, hash requirement, timeout) and add tests.

Do not leave docs claiming an action that `ACTION_REGISTRY` does not expose. Add a parity test (Task 7).

### Task 7 — Strengthen tests

- Split `tests/test_agent_contract.py` into contract (files exist) and behavior (`test_agent_behavior.py`).
- Add: `config.yaml` keys match what `Agent` reads; `init` is idempotent and seeds 3 tasks; documented actions == `ACTION_REGISTRY`.
- Close SQLite connections in `setup_agent` (current helper leaks them).
- Keep everything offline.

**Acceptance:** `python -m pytest -q` passes.

### Task 8 — Assets

Delete `assets/images/*.jpg` and `assets/images/__init__.py` unless they are intentionally documentation figures. If kept, move to `docs/assets/`, remove `__init__.py`, and reference them from `README.md`.

## 5. End-user target flow

```bash
git clone <repo> && cd sqlite-task-board
python -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
taskboard init        # migrate + seed + create workspace dirs (idempotent)
taskboard check       # clear PASS/FAIL, no traceback
taskboard status      # queue summary
taskboard run         # process the bootstrap tasks
```

## 7. Guardrails

- Update `AGENTS.md` and the static contract tests whenever the layout or required files change; they are the enforcement points.
- Keep `agent.py` as a single file. Do not introduce a package, ORM, or web layer.
- Never commit `tasks.db`, logs, or workspace output.
- Preserve security controls: `shell=False`, argument lists, timeouts, workspace boundary, protocol/host allowlists.
- No secrets in config, logs, or generated `.env` files.
- Do not broaden network or registry access to make tests pass.

## 8. Out of scope

Queue replenishment, multi-worker claiming/locking, new action types beyond Task 6, CLI subcommands beyond `init/check/status/run`, and any hosted or networked mode.

## 9. Suggested commit sequence

1. `chore: untrack runtime artifacts and expand .gitignore`
2. `refactor(config): keep a single canonical config.yaml`
3. `feat(cli): add init/status, honor AGENT_CONFIG, fail closed on config errors`
4. `build: replace requirements.txt with pyproject console script`
5. `docs: rewrite README quickstart and trim AGENTS protocol`
6. `test: cover init idempotency, config keys, and documented action parity`
